# `torchreid` is intentionally NOT `pip install`-able from this file: the PyPI package named
# "torchreid" is an unofficial third-party fork with no declared dependencies — confirmed by
# testing: `pip install torchreid` succeeds but `import torchreid` then fails with
# `ModuleNotFoundError: No module named 'scipy'`. The canonical source
# (KaiyangZhou/deep-person-reid) also cannot be `pip install -e .`'d on modern pip/setuptools:
# its setup.py needs numpy+Cython at BUILD time to compile an optional Cython-accelerated eval
# extension, but pip's isolated build env doesn't have them and nothing declares that
# requirement. See README.md "Cài torchreid" for the exact install steps actually used (clone
# + install these runtime deps + copy the package folder directly into site-packages, skipping
# the broken Cython-extension build — torchreid's own code already falls back to a pure-Python
# eval path with just a warning when that extension is absent, confirmed at runtime).
